# 科研工作台核对

按“读 → 核 → 提议 → 确认”完成核对。

1. 先调用 `medhelp_workbench` 的 `overview` 获取全局状态。只有在某项确实需要议程、纪要或行动项细节时，才调用 `meeting_get`；需要转写原文时再调用 `transcript_get`。
2. 将每个判断绑定到工具返回的证据，写明会议、纪要或行动项的标题与 ID。数据不足时标为“缺失信息”，不要根据记忆或常识补全工作台事实。
3. 输出四类清单：逾期、本周到期、下次组会要讲、缺失信息。没有内容的类别明确写“无”，不要编造项目。
4. 对每项建议给出下一步、建议截止时间及其依据。区分已经存在的记录和准备新增的草稿。
5. 需要写入工作台时，先把拟写入内容列成可选择清单，等待用户明确选择。未经用户确认，不得调用任何写入工具。
6. 用户确认后逐条调用相应写入工具，并只把返回 `confirmed: true` 的项目报告为已保存；失败或被拒绝的项目保持为未保存草稿。

不要直接读写 SQLite，不要用 shell 或 `curl` 绕过工具权限，也不要把一次批准解释为后续写入的永久授权。
