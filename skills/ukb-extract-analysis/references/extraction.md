# 提取输入与验证

## Parquet

使用显式提供的单个本地 `.parquet` 文件。`spec.yaml` 中的逻辑 `data_path` 保留溯源信息，`--data-file` 是用户确认的本地映射，不根据旧路径自动扫描数据盘。

通过 DuckDB 只投影请求列，验证所有请求列存在，验证整个源文件的 eid 非空且唯一。导出按 eid 排序；`--limit 20` 为前 20 行，不是随机样本；0 才表示全量。输出 Parquet 或 CSV，并保持原始列名和编码。CSV 不保留完整类型信息，日期/浮点等下游解释仍需字典。

查询元数据不需要 DuckDB；数据导出需要。脚本不接受任意 SQL，不隐式做 join 或行过滤。

## easyUKB RDS 切片

`--raw-root` 目录须有 `ID.xlsx`，含大写 `ID` 和 `name`。Python openpyxl 读取字段到文件的映射，实际列由计划给出。

`name` 可以是目录内相对路径、目录内绝对 `.rds` 路径，或唯一文件名/不带扩展名的 stem。仅在指定目录下解析匹配文件；同名文件多处出现、路径超出根目录、字段多次出现均失败。不会复制整个 raw-root。

Rscript 按需读取每个请求字段所在的 RDS 切片。每片必须是含 eid 的 data.frame，eid 唯一且非空。多个切片必须拥有相同参与者集合；按 eid 匹配后按请求顺序输出。参与者集合不同需要用户明确 join 规则，不能偷偷 inner/full join。常见的完整 cohort 字段切片可直接处理；组学子集不能套用这一规则。

RDS 无按列流式读取能力，内存至少要容纳一个完整切片和累积提取结果。这里不会先对整张超大 RDS 执行 `readRDS` 再承诺低内存。尚未切片的原始大表需另行设计预处理，或改用 Parquet。

输出 `data.rds`。脚本只在 stdout 返回行数；库错误细节不回显，避免 R 错误带出单元格内容。失败后本次临时目录清理，系统强制终止仍可能遗留 `.ukb-pending-*`，不能视为成功结果。

## 计划、编码与证据

两种提取方式均拒绝 NULL/NA、空字符串、纯空白字符串和重复的 eid；不通过自动填补或修剪 ID 来制造可匹配记录。

计划中的 Field ID、instance、array、物理列、来源上下文一并保存。所有提取输出都带本次 `coding_values.csv`；未自动解码或重编码。若从计划中删减列，只按确切 colname 修改，不改变列名或将别的数组解释成同一项。

原 skill 用 `intersect(required, ID)` 跳过缺列的示例不沿用：缺少任何请求变量须失败。数组上限不固定，`41270/41280` 等各自根据实际字典展开并核对配对。

交付时报告请求字段数、实际物理列数（是否含 eid）、输出行数、限制、文件格式、codebook 版本及未完成的验证。测试使用虚构数据；不能把虚构数据测试称为完整真实 UKB 队列验证。
